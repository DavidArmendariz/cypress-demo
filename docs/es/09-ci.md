# 9. Integración continua

*[English](../en/09-ci.md) · [Español](../es/09-ci.md)*

- CI ejecuta los mismos comandos que ejecutas en local. Ningún script exclusivo de CI.
- Arranca los servidores con tu gestor de procesos, nunca desde dentro de una spec.
- Separa el feedback rápido (tipos, lint) del lento (navegadores) en trabajos distintos.

## Estructura de trabajos

| Trabajo | Ejecuta | Por qué va aparte |
|---|---|---|
| Estático | comprobación de tipos, lint | Segundos. Detecta la mayoría de errores antes de arrancar un navegador. |
| End to end | la suite completa en navegador | Minutos. Necesita la aplicación en marcha. |
| Componente | specs de componente | No necesita servidores, así que corre en paralelo. |

Ejecútalos en paralelo. El tiempo total pasa a ser el del trabajo más lento, no la suma.

## Arrancar los servidores

```yaml
- uses: cypress-io/github-action@v7
  with:
    start: npm run dev
    wait-on: 'http://localhost:5180, http://localhost:3001/api/health'
    wait-on-timeout: 120
```

La action instala dependencias, cachea el binario de Cypress, arranca los servidores, espera a que
respondan, ejecuta la suite y lo apaga todo.

Dale a la API un endpoint `/api/health` trivial para que `wait-on` lo consulte. Esperar solo al cliente
no basta: un servidor de desarrollo puede estar sirviendo HTML mientras la API que tiene detrás todavía
está arrancando.

En local, `start-server-and-test` hace el mismo trabajo:

```bash
start-server-and-test dev http://localhost:5180 'cypress run'
```

Arrancar un servidor desde dentro de una spec con `cy.exec()` o `cy.task()` deja procesos huérfanos,
provoca conflictos de puertos en las reejecuciones y no te da nada útil cuando el servidor no arranca.

## Secretos

```yaml
env:
  CYPRESS_testUserEmail: qa-user@example.com
  CYPRESS_testUserPassword: ${{ secrets.TEST_USER_PASSWORD }}
```

`CYPRESS_<nombre>` rellena el entorno de Cypress, y `cy.env(['testUserPassword'])` lo lee exactamente
igual que lee el archivo local. Ver [07-secrets-and-env.md](07-secrets-and-env.md).

## Artefactos

```yaml
- uses: actions/upload-artifact@v7
  if: failure()
  with:
    name: cypress-screenshots
    path: cypress/screenshots
    if-no-files-found: ignore
    retention-days: 7
```

Solo `if: failure()`. Subir artefactos de ejecuciones verdes es coste puro.

Deja el vídeo desactivado por defecto. Es lento de grabar, grande de almacenar, y las capturas más el
command log responden a casi todas las preguntas. Actívalo para una investigación concreta.

## Reintentos

```ts
retries: { runMode: 2, openMode: 0 }
```

CI reintenta, las ejecuciones locales no. Una prueba que solo pasa al tercer intento sigue estando rota.
Las pruebas reintentadas se marcan en el resumen de la ejecución, y esa marca es un informe de error, no
una build verde. Revísala cada semana o se convertirá en parte del paisaje.

## Pull requests frente a main

Ejecuta la suite completa en los pull requests, para que los fallos queden asociados al cambio que los
causó. Ejecutarla solo en `main` significa enterarse después de mergear, cuando además ya es problema de
otra persona.

Usa `concurrency` para cancelar ejecuciones superadas en la misma rama:

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

## Escalar

Cuando la suite pase de unos diez minutos, paraleliza antes de que la gente empiece a saltársela.
Cypress Cloud aporta balanceo de carga entre contenedores, cancelación automática al primer fallo y
detección de inestabilidad:

```yaml
strategy:
  matrix:
    containers: [1, 2, 3]
# with:
#   record: true
#   parallel: true
```

Añádelo cuando el tiempo de ejecución lo justifique, no antes. Por debajo de diez minutos, la sobrecarga
de coordinación suele ser mayor que el ahorro.

## Un solo comando

Define un único punto de entrada que ejecute todo, y que CI llame exactamente a eso:

```bash
make verify   # tipos + lint + componente + end to end
```

Si está verde en tu máquina, CI no te va a sorprender con un comando distinto. Ver
[11-makefile-as-entrypoint.md](11-makefile-as-entrypoint.md).
